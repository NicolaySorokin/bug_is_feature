# Соответствие техническому заданию

Где и как выполнено каждое требование ТЗ «Система контроля и обработки
статистических данных по обучению студентов вузов и школ по ИТ-направлениям».
Пути интерфейса — пункты бокового меню; API — Swagger UI `/docs`.
Центральный объект — взаимодействие с вузом, договор — его необязательная
часть ([решения по бизнес-модели](business-model-decisions.md)).

## Требования к сервису (раздел 4)

| № | Требование | Как выполнено |
| --- | --- | --- |
| 4.1 | Каталоги (ИТ-продукты, ИТ-направления, вузы, ответственные) в БД, актуализация загрузкой xls/xlsx по маппингу полей | «Загрузка из Excel»: сводный каталог с полями из ТЗ (Название ВУЗа, Вендор, ПО, Номер договора, Подписание лицензии, Срок действия лицензии, Статус по передаче, ФИО Менеджера, Ответственные от ВУЗа, Комментарий), вузы, ответственные от вузов, ИТ-программы, ИТ-продукты, вендоры, анкеты LMS. Колонки сопоставляются автоматически по названиям и синонимам, сопоставление правится; пробная проверка показывает итог до записи. Сводный каталог загружается через модель взаимодействия (продукт — вместе с ИТ-программой), вуз узнаётся по ИНН или названию, новый — ждёт проверки. API `/imports`, код `backend/app/services/imports.py` |
| 4.2 | Отчёты по всем взаимодействиям с вузами за период | «Отчёты и статистика» → «Взаимодействие с вузами». API `/reports/preview`, `/reports/export` |

## UX/UI (раздел 8)

Десктопная и мобильная версии (меню выезжает, таблицы становятся
карточками, окна — на весь экран, схема процесса — списком этапов),
контраст текста не ниже WCAG AA, связанные блоки рядом («Сведения»
и «Обзор взаимодействия» над вкладками, карточка этапа рядом со схемой).

## Защита информации (152-ФЗ, приказ ФСТЭК № 117)

- Единая точка входа (Nginx); база, API и Keycloak напрямую не доступны.
- HTTPS с HSTS, Content-Security-Policy, запрет встраивания во фрейм.
- Идентификация и аутентификация — Keycloak в боевом режиме с хранением
  в PostgreSQL: вход только через страницу Keycloak (PKCE, без выдачи
  токена по паролю в обход неё), политика паролей (от 12 знаков, буквы
  разного регистра и цифры, не совпадает с логином), токены на 30 минут,
  блокировка при подборе пароля, журнал событий входа. Паролей
  в репозитории нет: учётными записями и паролями управляет
  администратор на сайте, обновления стенда их не трогают.
- Снаружи доступен только реалм системы: реалм `master` и консоль
  администратора Keycloak из интернета закрыты; служебные сведения
  (версии, среда, состояние кэша) без входа не отдаются.
- Разграничение доступа: роли, отдельные права и область данных
  проверяются сервером; у администратора бизнес-данных нет, расширение
  области — временно, с основанием и записью в журнале; отключённая
  учётная запись не может выполнить ни одного запроса.
- Регистрация событий: журнал изменений данных, прав и настроек с автором
  и значениями «было / стало»; персональные данные в журнале замаскированы.
- Минимизация персональных данных: из анкет LMS не сохраняются паспорт,
  СНИЛС, адрес и сведения о дипломе; заявки с ФИО и контактами видны
  только по отдельному праву «Персональные данные студентов».
- Контроль загружаемых файлов по типу и размеру.
- Резервное копирование: ежедневные копии базы системы, базы Keycloak
  и файлов вложений на сервере, 14 дней хранения, проверенная процедура
  восстановления (README, раздел «Боевой стенд»).

Организационные меры (модель угроз, уровень защищённости ИСПДн,
ответственный за обработку персональных данных) определяет оператор при
вводе в эксплуатацию.
