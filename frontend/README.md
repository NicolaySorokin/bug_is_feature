# Клиентская часть

Веб-интерфейс системы: React 18 + TypeScript, сборка Vite, дизайн-система
Ростелекома Atomaro. Одностраничное приложение — после действий страница
не перезагружается, обновляются только затронутые данные.

## Запуск в разработке

Нужны Node.js 22 и запущенный API (`make up` в корне или `uvicorn`
на порту 8000).

```bash
npm ci
npm run dev        # http://localhost:5173
```

Vite проксирует `/api` на `http://localhost:8000` (другой адрес —
переменная `VITE_DEV_API_URL`), поэтому клиент ходит на тот же путь
`/api/v1`, что и на стенде, и CORS не нужен.

Схему входа выбирает сервер (`GET /api/v1/meta/auth`), одна и та же
сборка работает везде:

- `AUTH_BACKEND=dev` — вместо формы входа список учётных записей, API
  получает пользователя в заголовках `X-Dev-User` и `X-Dev-Roles`;
- `AUTH_BACKEND=keycloak` — вход на странице Keycloak по Authorization
  Code + PKCE (keycloak-js, публичный клиент `edu-crm-web`). Токены живут
  в памяти и в `sessionStorage` вкладки и продлеваются перед запросом.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | сервер разработки с горячей перезагрузкой |
| `npm run build` | проверка типов и сборка в `dist/` |
| `npm run typecheck` | только проверка типов |
| `npm run lint` | ESLint |
| `npm run format` / `format:check` | Prettier: исправить / проверить |
| `npm test` | тесты Vitest |
| `npm run api:types` | типы API из `docs/openapi.json` |
| `npm run theme` | пересобрать тему Ростелекома `src/styles/rt-theme.css` |
| `npm run help:screenshots` | снимки экранов для руководств |

CI (задача «Клиентская часть») выполняет `npm ci`, сверку типов API,
`typecheck`, `lint`, `format:check`, `test` и `build`.

## Устройство

```
src/
  main.tsx, Root.tsx    запуск: вход, текущий пользователь, кэш запросов
  App.tsx               маршруты; страницы грузятся по мере надобности
  api/                  клиент HTTP, запросы и изменения, типы API
  auth/                 вход (Keycloak или заглушка) и права в интерфейсе
  layout/AppShell.tsx   каркас: боковое меню, верхняя панель, мобильное меню
  pages/                страницы разделов; contract/ — вкладки карточки договора,
                        reports/ — отчёт, статистика и заявки, admin/ — администрирование,
                        help/ — встроенные руководства
  features/workflow/    схема процесса: раскладка этапов и холст с масштабом
  charts/               диаграммы на SVG и CSS, у каждой есть табличный вид
  components/           таблица, окна, выбор файла, периода, множественный выбор
  lib/                  форматирование, подписи статусов, запоминание фильтров
  styles/               тема Ростелекома и стили приложения
public/help/            снимки экранов для руководств и схема архитектуры
scripts/                генератор темы и съёмка снимков экранов
```

**Данные.** Запросы идут через TanStack Query: ответы кэшируются, после
изменения сбрасываются только затронутые запросы. Ошибки API приходят
в едином формате `{code, message, details}` и показываются человеку
понятным текстом вместе с кодом.

**Запоминание действий** (требование 13 ТЗ). Фильтры реестров, отчётов
и журналов, выбранные колонки, черновики комментариев хранятся
в `localStorage` ([lib/storage.ts](src/lib/storage.ts)), фильтры
реестров ещё и в адресе страницы — ссылкой можно поделиться.

**Права.** Интерфейс прячет кнопки, недоступные роли
([auth/session.tsx](src/auth/session.tsx)), но решает всегда сервер.

**Диаграммы.** Столбцы одного цвета, значения подписаны, при наведении —
подсказка; кнопка «Показать таблицей» выводит те же цифры таблицей.
Файлы диаграмм PNG и PDF строит сервер, поэтому они совпадают с отчётом.

## Тема Ростелекома

Компоненты — из `@atomaro/ui-kit`. Пакет фирменной темы Atomaro закрытый,
поэтому тема повторена файлом `src/styles/rt-theme.css`: в токенах
стандартной темы акцентный синий заменён фиолетовым Ростелекома `#7700FF`
на тех же ступенях светлоты. Файл собирает `npm run theme`
([scripts/rt-theme.mjs](scripts/rt-theme.mjs)) — руками его не правят,
после обновления `@atomaro/ui-kit` скрипт запускают заново. Второй
фирменный цвет — оранжевый `#FF4F12`, шрифт — Manrope
(`@fontsource/manrope`, раздаётся со стенда).

## Типы API

`src/api/schema.d.ts` генерируется из `docs/openapi.json`:

```bash
make openapi          # в корне: выгрузить схему из кода API
npm run api:types     # здесь: пересобрать типы
```

CI не пропустит изменение API, если схема или типы отстали от кода.

## Сборка и образ

`Dockerfile` собирает клиентскую часть в образе Node.js и кладёт `dist/`
в образ Nginx `edu-crm-web`. На стендах Nginx берёт конфигурацию среды
из `cicd/<среда>/nginx.conf`: раздаёт интерфейс (любой адрес, кроме
файлов, отдаёт `index.html`), проксирует `/api`, `/docs` и Keycloak,
ставит заголовки безопасности. Файлы из `/assets/` с хешем в имени
кэшируются браузером на год, `index.html` — перепроверяется при каждом
заходе, так что после деплоя пользователи сразу получают новую версию.

Для сборки за корпоративным прокси с собственным корневым сертификатом
его можно передать секретом BuildKit, не записывая в образ:

```bash
docker build --secret id=ca,src=/path/to/ca.crt -t edu-crm-web frontend
```

## Снимки экранов для руководств

Руководства в разделе «Руководства» показывают снимки из `public/help/`.
Их снимает `npm run help:screenshots` (Playwright) со стенда
с демоданными в режиме разработки:

```bash
BASE=http://localhost:5173 KEYCLOAK_BASE=http://localhost:8088 npm run help:screenshots
```

`KEYCLOAK_BASE` — адрес стенда с Keycloak для снимка страницы входа,
без него этот снимок пропускается. Playwright в зависимости проекта
не входит: `npx playwright install chromium` или путь к установленному
пакету в `PLAYWRIGHT_PATH`.
